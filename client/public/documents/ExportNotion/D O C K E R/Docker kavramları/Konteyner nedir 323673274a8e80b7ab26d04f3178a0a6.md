# Konteyner nedir?

**Açıklama**

Diyelim ki üç ana bileşeni olan bir web uygulaması geliştiriyorsunuz: bir React frontend, bir Python API ve bir PostgreSQL veritabanı. Bu projede çalışmak istiyorsanız Node, Python ve PostgreSQL yüklemeniz gerekir.

Peki, takımınızdaki diğer geliştiricilerle aynı versiyonlara sahip olduğunuzdan nasıl emin olursunuz? Ya da CI/CD sisteminiz? Ya da prodüksiyonda kullanılan versiyonlar?

Python (veya Node veya veritabanı) versiyonunun, makinenizde zaten yüklü olanlardan etkilenmediğini nasıl garanti edersiniz? Olası çakışmaları nasıl yönetirsiniz?

İşte konteynerler devreye giriyor!

Konteyner nedir? Basitçe, konteynerler uygulamanızın her bileşeni için izole edilmiş proseslerdir. Her bileşen — frontend React uygulaması, Python API motoru ve veritabanı — kendi izole ortamında çalışır ve makinenizdeki diğer her şeyden tamamen ayrıdır.

Konteynerleri harika yapan özellikler şunlardır:

- **Self-contained**: Her konteyner, host makinedeki önceden yüklenmiş bağımlılıklara ihtiyaç duymadan çalışmak için gerekli her şeye sahiptir.
- **Isolated**: Konteynerler izole çalıştığı için host ve diğer konteynerler üzerinde minimal etkiye sahiptir, bu da uygulamalarınızın güvenliğini artırır.
- **Independent**: Her konteyner bağımsız olarak yönetilir. Bir konteyneri silmek diğerlerini etkilemez.
- **Portable**: Konteynerler her yerde çalışabilir! Geliştirme makinenizde çalışan bir konteyner, veri merkezi veya bulutta da aynı şekilde çalışacaktır.

**Konteynerler vs sanal makineler (VMs)**

VM’ler, kendi kernel’ı, donanım sürücüleri, programları ve uygulamaları olan tam bir işletim sistemi içerir. Sadece tek bir uygulamayı izole etmek için bir VM açmak büyük bir overhead yaratır.

Konteyner, çalışması için gereken tüm dosyaları içeren izole bir prosesdir. Birden fazla konteyner çalıştırırsanız, hepsi aynı kernel’ı paylaşır ve daha az altyapıyla daha fazla uygulama çalıştırabilirsiniz.

```
VM ve konteynerleri birlikte kullanmak
Bulut ortamında, genellikle sağlanan makineler VM’dir. Ancak bir uygulama çalıştırmak için bir makine sağlamak yerine, konteyner runtime’a sahip bir VM birden fazla konteyner uygulaması çalıştırabilir, böylece kaynak kullanımı artar ve maliyet düşer.
```

**Deneyin**

Bu pratikte, Docker Desktop GUI kullanarak bir Docker konteyneri çalıştırmayı göreceksiniz.

**GUI kullanarak**

1. Docker Desktop’u açın ve üst navigasyon çubuğundaki **Search** alanını seçin.
2. Arama alanına **`welcome-to-docker`** yazın ve **Pull** butonuna tıklayın.

![](https://s3.eu-north-1.amazonaws.com/lms.goit.files/a3f57f75-01f5-4be0-baa1-cc3a0bfd294fimage.png)

1. İmaj başarıyla çekildikten sonra **Run** butonunu seçin.
2. **Optional settings** bölümünü genişletin.
3. **Container name** alanına **`welcome-to-docker`** yazın.
4. **Host port** alanına **`8080`** yazın.

![](https://s3.eu-north-1.amazonaws.com/lms.goit.files/b9d90a5f-a410-49c7-853b-da02c8f59379image.png)

1. **Run** butonuna tıklayarak konteyneri başlatın.

Tebrikler! İlk konteynerinizi çalıştırdınız! 🎉

**CLI kullanarak**

1. CLI terminalinizi açın ve şu komutla bir konteyner başlatın:

`docker run -d -p 8080:80 docker/welcome-to-docker`

Bu komut size konteynerin tam ID’sini döndürecektir.

Tebrikler! İlk konteynerinizi CLI ile çalıştırdınız! 🎉

**Çalışan konteynerleri görüntüleme**

Konteynerin çalışıp çalışmadığını doğrulamak için:

`docker ps`

Çıktı örneği:

`CONTAINER ID   IMAGE                      COMMAND                  CREATED          STATUS          PORTS                      NAMES
a1f7a4bb3a27   docker/welcome-to-docker   "/docker-entrypoint.…"   11 seconds ago   Up 11 seconds   0.0.0.0:8080->80/tcp       gracious_keldysh`

Bu konteyner basit bir web sunucusu çalıştırır. Daha karmaşık projelerde farklı parçaları farklı konteynerlerde çalıştırırsınız (örn. **frontend**, **backend**, **database**).

```
İpucu: docker ps sadece çalışan konteynerleri gösterir. Duranları görmek için -a bayrağı ekleyin: docker ps -a.
```

**Frontend’e erişim**

Konteyneri başlattığınızda, konteynerin bir portunu makinenize açtınız. Bu, konteynerin izole ortamına bağlanmanızı sağlayacak bir yapılandırma gibidir.

Bu konteyner için frontend, **`8080`** portundan erişilebilir. Web sitesini açmak için container **Port(s)** kolonundaki linki seçin veya tarayıcıda [http://localhost:8080](http://localhost:8080/)adresini ziyaret edin.

**Konteynerleri görüntüleme**

Tüm konteynerlerinizi Docker Desktop Dashboard’un **Containers** görünümünden görebilirsiniz.

![](https://s3.eu-north-1.amazonaws.com/lms.goit.files/66d88b58-02d9-4819-a2bd-fd2c6abb162bimage.png)

**Konteyneri durdurma**

**`docker/welcome-to-docker`** konteyneri çalışmaya devam eder. Konteyneri durdurmak için:

1. `docker ps` komutuyla konteyner ID’sini alın.
2. ID veya ismi kullanarak:

`docker stop <container-id>`

```
İpucu: ID’nin tamamını yazmanıza gerek yok, benzersiz olması yeterlidir. Örnek:
```
