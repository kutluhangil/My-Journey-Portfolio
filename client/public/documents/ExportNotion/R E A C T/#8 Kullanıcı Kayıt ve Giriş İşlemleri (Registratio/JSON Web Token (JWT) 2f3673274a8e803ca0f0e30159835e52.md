# JSON Web Token (JWT)

Yetkilendirme mekanizmalarından biri JWT (JSON Web Token)’dir. Token'lar, frontend'den backend'e yapılan her istek için bir yetkilendirme aracı olarak kullanılır.

Token'lar, backend'de sunucuda saklanan gizli bir anahtara ve kullanıcının benzersiz verilerine (örneğin e-posta gibi) dayalı olarak oluşturulur. Sonuç olarak, token frontend'de saklanır ve herhangi bir isteğin yetkilendirilmesi gerektiğinde kullanılır.

Her token, üç bloktan oluşan benzersiz bir şifrelenmiş dizedir: başlık (header), veri seti (payload) ve imza (signature). Bir saldırgan, header veya payload verilerini değiştirmeye çalışırsa, token geçersiz hale gelir çünkü imza, orijinal verilere karşılık gelmez. Saldırganın yeni bir imza oluşturması mümkün değildir, çünkü şifreleme için gereken gizli anahtar sadece sunucuda saklanmaktadır.

## **🔐 JSON Web Token (JWT) Nedir?**

**JWT**, frontend ile backend arasında **yetkilendirme (authorization)** için kullanılan bir **kimlik kartıdır**.

> “Bu isteği yapan kullanıcı kim ve buna izni var mı?”
> 

> Backend bu sorunun cevabını
> 
> 
> **JWT**
> 

---

## **🔁 JWT Nasıl Çalışır? (Akış)**

### **1️⃣ Kullanıcı giriş yapar**

- Email + şifre backend’e gönderilir
- Backend doğrular (**authentication**)

### **2️⃣ Backend JWT üretir**

- Kullanıcının bilgilerine göre
- Gizli bir anahtar (secret key) kullanarak

### **3️⃣ JWT frontend’e gönderilir**

- Frontend token’ı saklar (genelde localStorage)

### **4️⃣ Frontend her istekte JWT gönderir**

```
Authorization: Bearer JWT_TOKEN
```

### **5️⃣ Backend token’ı kontrol eder**

- Geçerli mi?
- Bozulmuş mu?
- Süresi dolmuş mu?

➡️ Geçerliyse: **isteğe izin verilir**

---

## **🧱 JWT 3 Parçadan Oluşur**

JWT tek bir string gibi görünür ama **3 bloktur**

Araları . (nokta) ile ayrılır:

```
HEADER.PAYLOAD.SIGNATURE
```

Örnek:

```
eyJhbGciOiJIUzI1NiJ9
.
eyJlbWFpbCI6ImFiY0BleGFtcGxlLmNvbSJ9
.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

---

## **1️⃣ Header (Başlık)**

**Token hakkında bilgi verir**

Örnek:

```
{
  "alg": "HS256",
  "typ": "JWT"
}
```

- alg → hangi şifreleme algoritması
- typ → token türü

📌 **Bu kısım şifrelenmez**, sadece encode edilir.

---

## **2️⃣ Payload (Veri Seti)**

**Kullanıcıya ait bilgiler burada olur**

Örnek:

```
{
  "email": "user@example.com",
  "id": "12345",
  "exp": 1710000000
}
```

- Kullanıcıyı tanımlar
- Yetkilendirme bu bilgiye göre yapılır

📌 **Payload da şifrelenmez**, okunabilir

👉 O yüzden **şifre gibi hassas veri KONMAZ**

---

## **3️⃣ Signature (İmza) ⭐ EN ÖNEMLİ KISIM**

**JWT’nin güvenliğini sağlayan yer burası**

Signature şu şekilde üretilir:

```
HMACSHA256(
  base64UrlEncode(header) +
  "." +
  base64UrlEncode(payload),
  SECRET_KEY
)
```

### **🔑 SECRET_KEY**

- Sadece backend bilir
- Frontend veya saldırgan asla bilemez

---

## **🔥 Neden Güvenli?**

### **Senaryo: Saldırgan payload’ı değiştiriyor**

```
{
  "email": "admin@example.com"
}
```

❌ Sorun:

- Header + payload değişti
- Ama **signature aynı kaldı**

➡️ Backend kontrol eder:

- Header + payload + secret key
- Yeni imza ≠ eski imza

🚫 **Token geçersiz**

---

## **❗ Önemli Nokta**

> JWT
> 
> 
> **şifreleme değil**
> 
> **imzalama**
> 
- Veri gizli değil
- Veri **değiştirilemez**

Bu yüzden:

- Kimlik bilgisi güvenli
- Veri bütünlüğü korunur

---

## **⏱️ Token Süresi (exp)**

JWT genelde **süreli** olur:

```
{
  "exp": 1710000000
}
```

- Süre dolunca:
    - Backend token’ı reddeder
    - Kullanıcı tekrar login olur

➡️ Güvenlik artar

---

## **🧠 JWT Nerede Saklanır?**

Frontend tarafında genelde:

- localStorage ✅ (en yaygın)
- sessionStorage
- httpOnly cookie (en güvenlisi)

📌 Eğitim projelerinde genelde localStorage kullanılır

---

## **Authentication vs JWT (Net)**

- **Authentication** → Email + şifre
- **JWT** → Giriş sonrası verilen yetki anahtarı
- **Authorization** → JWT ile yapılır

---

## **🧪 Kısa Özet**

- JWT = yetkilendirme token’ı
- Frontend her istekte gönderir
- Backend secret key ile doğrular
- 3 parçadan oluşur:
    - Header
    - Payload
    - Signature
- Payload okunabilir ama **değiştirilemez**
- İmza bozulursa token geçersiz
