### **Mantık Değişimi (Local Storage 🆚 Backend)**

Önceki ödevinde uygulamanın hafızası senin tarayıcındı (**Local Storage**). Yani sen bir kişiyi kaydettiğinde, o bilgi sadece senin bilgisayarında kalıyordu.

**Şimdiki Durum:** Artık bir **Backend** (MockAPI) var. Yani veriler internet üzerindeki bir sunucuda duruyor.

- **Sorun:** Sunucuya gitmek, veriyi almak veya kaydetmek anlık değildir. Zaman alır (yarım saniye, 1 saniye vb.).
- **Çözüm:** Redux'ın bu "bekleme", "başarılı olma" veya "hata alma" durumlarını yönetmesi gerekir.

### **ADIM 1: Postacıları Hazırladık (contactsOps.js) 📬**

Eskiden "Ekle" butonuna bastığında Redux anında listeye eklerdi. Şimdi ise Redux'ın önce sunucuya (Backend'e) gidip "Ben bunu eklemek istiyorum" demesi lazım.

Bunun için özel "Postacı" fonksiyonlar yazdık. Redux dünyasında bunlara **Thunk** diyoruz.

**Dosya:**

src/redux/contactsOps.js

1. **`fetchContacts`**: "Hey sunucu, bana kayıtlı rehberi ver."
2. **`addContact`**: "Hey sunucu, bu yeni kişiyi listene ekle."
3. **`deleteContact`**: "Hey sunucu, şu ID'li kişiyi sil."

**Örnek Kod Açıklaması:**

```
javascript

exportconstfetchContacts=createAsyncThunk(
"contacts/fetchAll",// 1. Eylemin adı
async (_,thunkAPI)=> {// 2. Yapılacak iş (Asenkron)
try {
constresponse=awaitaxios.get("/contacts");// Sunucuya git
returnresponse.data;// Veriyi dön
    }catch (e) {
returnthunkAPI.rejectWithValue(e.message);// Hata varsa dön
    }
  }
);

```

### **ADIM 2: Beyni Eğittik (contactsSlice.js) 🧠**

Redux'ın (Slice) artık sadece listeyi tutması yetmez. İşlemin durumunu da bilmesi gerekir.

**Durum (State) Yapısı Değişti:**

```
javascript

constinitialState= {
items: [],// Kişiler
loading:false,// Şu an işlem yapıyor muyum? (Dönen daire gösterelim mi?)
error:null,// Bir hata oldu mu?
};

```

**ExtraReducers Kullandık:** Eskiden

```
reducers
```

içinde "EKLE", "SİL" diyorduk. Şimdi

**extraReducers**

kullanıyoruz çünkü işlem bizim kontrolümüzde değil, sunucudan gelecek cevaba göre değişiyor.

Her işlemin (Örn:

```
fetchContacts
```

) 3 aşamasını dinliyoruz:

1. **`.pending` (Bekliyor):** "İşlem başladı, kullanıcıya beklemesini söyle." ->
    
    ```
    loading = true
    ```
    
2. **`.fulfilled` (Başarılı):** "Veri geldi!" -> ,
    
    ```
    loading = false
    ```
    
    ```
    items = gelenVeri
    ```
    
3. **`.rejected` (Hata):** "Eyvah sunucu hata verdi." -> ,
    
    ```
    loading = false
    ```
    
    ```
    error = hataMesajı
    ```

### **ADIM 3: Akıllı Seçici (contactsSlice.js - Memoization) 🤓**

Ödevin en teknik kısımlarından biri buydu. "Seçicilerin Hafızaya Alınması".

**Sorun:** Senin rehberinde 10.000 kişi olsa, arama kutusuna her harf yazdığında veya Redux'ta ilgisiz bir şey değiştiğinde (örneğin yükleme ikonu döndüğünde) React tüm listeyi baştan sona tekrar filtrelemeye çalışır. Bu uygulamayı yavaşlatır.

**Çözüm (**

```
createSelector
```

**):**

Redux Toolkit'ten gelen bu özellik sayesinde bir "Akıllı Filtre" yaptık.

```
javascript

exportconstselectFilteredContacts=createSelector(
  [selectContacts,selectNameFilter],// Girdiler (Liste ve Filtre Kelimesi)
  (contacts,filter)=> {
// Sadece yukarıdaki girdiler değişirse burası çalışır!
returncontacts.filter(contact=>
contact.name.toLowerCase().includes(filter.toLowerCase())
    );
  }
);

```

Bu fonksiyon, eğer liste ve filtre kelimesi değişmediyse, hesaplama yapmaz; hafızasındaki eski sonucu verir. **Performans artışı!** 🚀
