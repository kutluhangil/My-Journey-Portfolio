# Task - Çözüm

### **Bölüm 1: Kodlama Mantığı (JavaScript)**

Burada yaptığımız değişiklikler, modern JavaScript standartlarına uygun, daha okunabilir ve yönetilebilir bir yapı kurmak içindi.

### **1. Fetch yerine Axios Neden ve Nasıl?**

Eski

fetch yönteminde iki adım uyguluyorduk: Önce veriyi çek, sonra

```
.json()
```

diyerek çevrilmesini bekle. Hata yakalamak için de ayrıca

```
if (!response.ok)
```

kontrolü yapmamız gerekiyordu.

**Axios ile ne değişti?**

- **Otomatik Dönüşüm:** Axios, gelen cevabı (response) otomatik olarak JSON formatına çevirir.  dememize gerek kalmaz; direkt  ile veriye ulaşırız.
    
    ```
    response.json()
    ```
    
    ```
    response.data
    ```
    
- **Hata Yönetimi:** Sunucudan hata (404, 500 vb.) gelirse Axios bunu otomatik olarak "Hata" sayar ve  bloğuna atar. Elle kontrol etmemize gerek kalmaz.
    
    ```
    catch
    ```
    
- **Parametre Yönetimi:** URL'nin sonuna  yazmak yerine,  objesi olarak tertemiz bir şekilde veririz.
    
    ```
    ?key=...&q=...
    ```
    
    ```
    params
    ```
    

### **2. Async/Await Nedir?**

Eskiden

```
.then()
```

zincirleri kullanıyorduk. Bu, kodun sağa doğru kaymasına ve "callback cehennemi"ne yol açabiliyordu.

- `async`: Bir fonksiyona "Senin içinde beklemem gereken işlemler olabilir" der.
- `await`: "Bu işlem bitene kadar bir alt satıra geçme, bekle" der.
- **Sonuç:** Kodumuz sanki senkron (satır satır) çalışıyormuş gibi görünür ve okunması çok daha kolaydır.

### **3. Sayfalandırma (Pagination) Mantığı**

Tüm görselleri tek seferde çekemeyiz. Sayfa sayfa çekmemiz gerekir. Bunu yönetmek için değişkenler (state) kullandık:

- `page`: Şu an kaçıncı sayfadayız? (Başlangıç: 1)
- `perPage`: Sayfa başına kaç resim gelecek? (40)
- `totalHits`: Toplam kaç resim var?

**Senaryo 1: Yeni Arama Yapıldığında**

1. `page` değişkenini **1**'e sıfırlarız.
2. Galeriyi () temizleriz.
    
    ```
    innerHTML = ""
    ```
    
3. "Load More" butonunu gizleriz.

**Senaryo 2: "Load More" Tıklandığında**

1. `page` değişkenini **1 artırırız** ().
    
    ```
    page += 1
    ```
    
2. Gelen yeni resimleri eskilerin altına **ekleriz** ( ile). *Eğer `innerHTML = ...` yapsaydık eskiler silinirdi.*
    
    ```
    insertAdjacentHTML
    ```
    
3. Sayfayı aşağıya doğru yumuşakça kaydırırız ().
    
    ```
    window.scrollBy
    ```
    

**Senaryo 3: Son sayfaya geldik mi?**

- Basit bir matematik: .
    
    ```
    Toplam Resim / Sayfa Başına Resim = Toplam Sayfa Sayısı
    ```
    
- Örneğin 100 resim var, sayfada 40 resim gösteriyoruz.  -> Yani toplam **3** sayfa var ( ile yukarı yuvarlarız).
    
    ```
    100 / 40 = 2.5
    ```
    
    ```
    Math.ceil
    ```
    
- Eğer  ise, artık yüklenecek bir şey kalmamıştır. Butonu gizle ve "Bitti" mesajını göster.
    
    ```
    page >= 3
    ```

### **Bölüm 2: Yayınlama Mantığı (Deployment)**

Projeyi GitHub Pages üzerinde yayınlarken yaşadığımız sorunlar ve çözümleri:

### **1. Vite "Base" Ayarı (Neden Sayfa Boş Geldi?)**

Normalde Vite, projenin bir alan adının kök dizininde (örneğin

```
google.com/
```

) çalışacağını varsayar. Dosyaları

```
/style.css
```

gibi arar.

Ancak GitHub Pages'da adresimiz şöyledir:

```
kutluhangil.github.io/goit-js-hw-12/
```

. Yani projemiz

```
/goit-js-hw-12/
```

klasörü altında çalışıyor. Vite'a bunu söylemezsek, dosyaları yanlış yerde arar ve sayfa beyaz/boş çıkar.

- **Çözüm:** **vite.config.js** dosyasına  satırını ekledik. Böylece Vite, tüm dosya yollarının başına bu klasör adını ekledi.
    
    ```
    base: '/goit-js-hw-12/'
    ```
    

### **2. GitHub Actions (Otomasyon)**

İlk ödevlerde "Deploy from Branch" (gh-pages dalından yükle) seçeneğini kullanmıştın. Bu sefer "GitHub Actions" seçtiğin için, GitHub senden bir "tarif" bekledi: *"Bu siteyi nasıl inşa edeceğim?"*

Biz de

.github/workflows/deploy.yml dosyasını oluşturarak GitHub'a şu tarifi verdik:

1. **Checkout:** Kodumu depodan al.
2. **Setup Node:** Bilgisayara Node.js kur (tıpku senin bilgisayarındaki gibi).
3. **Install:**  (veya ) ile paketleri yükle.
    
    ```
    npm install
    ```
    
    ```
    npm ci
    ```
    
4. **Build:**  komutunu çalıştır. (Bu komut  klasörünü oluşturur).
    
    ```
    npm run build
    ```
    
    ```
    dist
    ```
    
5. **Upload & Deploy:** Oluşan bu  klasörünü al ve GitHub Pages'a yükle.
    
    ```
    dist
    ```
    

**Son Hata Neydi?** Tarif dosyasında (

```
yaml
```

), GitHub'ın tanımadığı fazladan bir ayar (

```
globals
```

) kalmıştı. Bu, sanki yemek tarifine "Tencereyi uzaya fırlat" yazmak gibiydi; GitHub ne yapacağını bilemedi ve hata verdi. O satırı silince tarif düzeldi ve yemek pişti! 🍳
