## **📄 Sayfalandırma (Pagination) Nedir?**

**Amaç:**

Büyük veri koleksiyonlarını (binlerce kayıt) **parça parça** yüklemek.

👉 Tüm veriyi tek seferde almak:

- Yavaş
- Çok internet tüketir
- Tarayıcıyı ve sunucuyu yorar

👉 Çözüm: **Sayfalandırma**

- Her istekte **sadece belirli sayıda kayıt** alınır
- Kullanıcı isterse “Daha fazla yükle” ile devam eder

---

## **⚙️ Nasıl Çalışır?**

Sayfalandırma genelde **2 parametreyle** yapılır:

### **1️⃣ Kaç öğe gelsin? → limit**

- Bir istekte kaç kayıt geleceğini belirler

```
_limit=5
```

### **2️⃣ Hangi grup (sayfa)? → page**

- Kaçıncı grup verinin alınacağını belirler

```
_page=3
```

### **🔗 Örnek URL**

```
https://jsonplaceholder.typicode.com/posts?_limit=5&_page=3
```

➡️ Anlamı:

**Her sayfada 5 post getir, 3. sayfayı al**

---

## **🔁 “Daha Fazla Yükle” Mantığı**

1. Başta:

```
let page = 1;
const limit = 5;
```

1. Her başarılı istekte:

```
page += 1;
```

1. Yeni gelen veriler:
- Eskilerin **üstüne eklenir**
- Liste sıfırlanmaz

---

## **🚫 Koleksiyon Bitti mi? (Son Kontrolü)**

Bazı backend’ler toplam veri sayısını vermez (JSONPlaceholder gibi).

Bu durumda **frontend hesaplar**.

### **Örnek:**

```
const totalItems = 100;
const limit = 30;
const totalPages = Math.ceil(totalItems / limit);
```

### **Kontrol:**

```
if (page > totalPages) {
  iziToast.error({
    message: "We're sorry, there are no more posts to load"
  });
}
```

➡️ Artık veri yoksa:

- Yeni istek atılmaz
- Kullanıcıya mesaj gösterilir

## **📊 Özet Tablo**

| **Kavram** | **Ne İşe Yarar** |
| --- | --- |
| Pagination | Veriyi parça parça almak |
| _limit | Bir istekte kaç kayıt geleceği |
| _page | Kaçıncı veri grubunun alınacağı |
| page değişkeni | Her “Daha fazla yükle”de artar |
| totalPages | Toplam kaç sayfa olduğunu gösterir |
| Koleksiyon sonu | Yeni veri yoksa kullanıcı uyarılır |
| iziToast | “Daha fazla veri yok” mesajı göstermek |
