# fs Modülü

Node.js'in en önemli özelliklerinden biri, tarayıcılardan farklı olarak dosyalarla çalışabilme yeteneğidir. Bu işlemler için, dosya ve klasörlerle çalışmayı sağlayan özel bir [`fs` modülü](https://nodejs.org/api/fs.html) bulunmaktadır.

Ayrıca, dosyalarla çalışırken **`path` modülü** de sıkça işimize yarar.

`fs` modülü ile örnekler incelemeye geçmeden önce, **Node.js** kütüphanelerinin genel çalışma prensiplerine kısaca göz atalım.

Çoğu **Node.js** modülünde, fonksiyonlar üç farklı şekilde sunulur: senkron fonksiyonlar, geri çağırma (callback) tabanlı asenkron fonksiyonlar ve promise tabanlı asenkron fonksiyonlar. Ancak, bazı modüller (örneğin, `path` modülü) bu yaklaşımlardan sapmalar gösterebilir.

Aşağıda, bu yaklaşımlar arasındaki farkları ve her birinin kullanım alanlarını açıklayacağız.

1. Senkron Fonksiyon. Genellikle, bu tür yöntemlerin adında `sync` ifadesi bulunur.

```
import fs from 'node:fs';

const fileContent = fs.readFileSync('path_to_file');
```

Senkron işlemler, işlemin tamamlanmasını bekleyene kadar diğer tüm işlemleri durdurur. Bu durum, performansı olumsuz etkileyebilir. Örneğin, bir süreç senkron bir işlem nedeniyle engellenirse, diğer işlemler işlenemez.
Senkron fonksiyonlar, genellikle performansın kritik olmadığı ve işlemin yalnızca bir kez yapılmasının yeterli olduğu durumlarda tercih edilir. Örneğin, uygulama başlatılmadan önce yapılandırma dosyasını okumak gibi durumlarda kullanabilirsiniz.

1. Callback ile Asenkron Fonksiyonlar

```
import fs from 'node:fs';

fs.readFile('path_to_file', (err, fileContent) => {
	/* kodunuz */
});
```

Bu yaklaşım, senkron işlemlerden farklı olarak, işlem sırasında uygulamanın geri kalanını engellemez ve daha yüksek performans sağlar.

**Node.js**'de callback'ler, hata öncelikli bir yapıya sahiptir. Geri çağırma fonksiyonları genellikle son argüman olarak kullanılır ve bu fonksiyonun ilk parametresi hata bilgisini taşır.

Bu yaklaşımın avantajı, en yüksek performansı sağlamasıdır. Bu seçenek, sözleşmelerle olan seçeneğe göre birkaç kat daha hızlı çalışacaktır (aşağıya bakın).

Dezavantajı ise, kod okunabilirliği düşebilir. Özellikle iç içe geçmiş callback'ler ("callback hell") oluştuğunda kod karmaşık hale gelir:

```
import fs from 'node:fs';

fs.readFile('path_to_file', (err, fileContent) => {
		someOtherFunctionWithCallback(fileContent, (err, data) => {
			anotherFunctionWithCallback(data, () => {....})
		}
});
```

Kodun okunabilirliğini artırmak için, performanstan makul ölçüde ödün vermek genellikle tercih edilir. Örneğin, bir **for** döngüsü, diziler üzerinde işlem yapan **map**, **filter** gibi yöntemlerden daha hızlı olabilir. Ancak bu yöntemler daha özlü ve anlaşılır olduğu için çoğu geliştirici tarafından tercih edilir.

Bu tür bir performans-fonksiyon seçimi genellikle şu durumlarda gereklidir:

- **Performansın kritik olduğu yerler**: Örneğin, performansa duyarlı kütüphaneler veya altyapı kodları geliştirirken.
- **Belirgin performans sorunları**: Uygulamanızın performansı ciddi şekilde etkileniyorsa.

3. Promise Tabanlı Asenkron Fonksiyonlar

```
import fs from 'node:fs/promises';

const fileContent = await fs.readFile('path_to_file');
```

Promise tabanlı yaklaşım, genellikle en çok tercih edilen yöntemdir. Hem engelleyici değildir hem de senkron kodlara benzer bir okunabilirlik sağlar. Bu yöntem, modern JavaScript özelliklerini kullanarak kodun daha temiz ve düzenli yazılmasını mümkün kılar.
