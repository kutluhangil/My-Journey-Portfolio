# Oturum (session)

Web geliştirme bağlamında, oturum (session), istemci (genellikle bir web tarayıcısı) ile sunucu arasındaki farklı istekler ve yanıtlar arasında durumu saklamaya olanak tanıyan bir mekanizmadır. Oturumlar, belirli bir süre boyunca kullanıcıya veya web sitesiyle olan etkileşimin durumuna dair bilgileri saklamak için kullanılır.

Oturumların temel yönleri şunlardır:

1. **Oturum Kimliği (Session ID):** Her oturum, istemci ile sunucu arasındaki bilgileri ilişkilendirmek için kullanılan benzersiz bir kimliğe sahiptir. Oturum kimliği genellikle çerezler (cookies) aracılığıyla iletilir veya URL’ye dahil edilir.
2. **Durum Saklama:** Oturumlar, belirli bir kullanıcıyla ilişkili durumu sunucuda saklamaya olanak tanır. Bu veriler, sisteme giriş bilgileri, alışveriş sepeti, kullanıcı ayarları ve diğer bilgileri içerebilir. Bizim durumumuzda oturum yalnızca yetkilendirme ile ilgili olacaktır, ancak gerektiğinde genişletilebilir. Ayrıca, oturumda yalnızca kaybı kritik olmayan verilerin saklanabileceğini unutmayın.
3. **Süre:** Oturumların sınırlı bir geçerlilik süresi olabilir; örneğin, belirli bir dakika veya saat sayısı. Bu, oturum verilerinin aktif kalacağı süreyi belirler.
4. **Güvenlik:** Bazı oturum mekanizmaları, yetkisiz erişimi önlemek için verileri şifreleme veya diğer yöntemler kullanarak ek koruma sağlar.
5. **Sunucu ve İstemci Rolleri:** Sunucu, oturum verilerini saklar ve yönetirken, istemci (genellikle bir çerez aracılığıyla) oturum kimliğini içerir ve her istekte sunucuya gönderir.

Oturumlar sayesinde web siteleri, belirli bir kullanıcıyla ilişkili bilgileri saklayabilir ve kişiselleştirilmiş ve güvenli bir kullanım deneyimi sunabilir.

Oturumlarla çalışmak için yeni bir koleksiyon oluşturacağız:

```
// src/db/models/session.js

import { model, Schema } from 'mongoose';

const sessionsSchema = new Schema(
  {
    userId: { type: Schema.Types.ObjectId, ref: 'users' },
    accessToken: { type: String, required: true },
    refreshToken: { type: String, required: true },
    accessTokenValidUntil: { type: Date, required: true },
    refreshTokenValidUntil: { type: Date, required: true },
  },
  { timestamps: true, versionKey: false },
);

export const SessionsCollection = model('sessions', sessionsSchema);
```

Oturumumuz şunlardan oluşacaktır:

1. **Erişim (Access) Token:** Kısa ömürlü (örneğin, 15 dakika) bir token. Her HTTP isteğinde **`Authorization`** başlığına eklenerek sunucuya gönderilir.
2. **Access Token Geçerlilik Süresi:** Access tokenin geçerli olduğu süre.
3. Yenileme( Refresh) Tokeni — daha uzun ömürlü (bu durumda 1 gün, ancak daha fazla da olabilir) bir token, ayrı bir uç noktada yeni bir erişim + yenileme tokeni çifti ile değiştirilebilir. Çerezlerde saklanır (bunlar hakkında birazdan daha fazla konuşacağız).
4. **Refresh Token Geçerlilik Süresi:** Refresh tokenin geçerli olduğu süre.
5. Oturumun ait olduğu kullanıcının kimliği.

Sabitler dosyasına yeni sabitler ekleyeceğiz:

```
// src/constants/index.js

/* Diğer dosya kodları */

export const FIFTEEN_MINUTES = 15 * 60 * 1000;
export const ONE_DAY = 24 * 60 * 60 * 1000;
```

Artık oturum oluşturma işlevselliğini oluşturabiliriz:

```
// src/services/auth.js

import { randomBytes } from 'crypto';
import bcrypt from 'bcrypt';
import createHttpError from 'http-errors';

import { FIFTEEN_MINUTES, ONE_DAY } from '../constants/index.js';
import { SessionsCollection } from '../db/models/session.js';

/* Diğer dosya kodları */

export const loginUser = async (payload) => {
  const user = await UsersCollection.findOne({ email: payload.email });
  if (!user) {
    throw createHttpError(404, 'User not found');
  }
  const isEqual = await bcrypt.compare(payload.password, user.password);

  if (!isEqual) {
    throw createHttpError(401, 'Unauthorized');
  }

  await SessionsCollection.deleteOne({ userId: user._id });

  const accessToken = randomBytes(30).toString('base64');
  const refreshToken = randomBytes(30).toString('base64');

  return await SessionsCollection.create({
    userId: user._id,
    accessToken,
    refreshToken,
    accessTokenValidUntil: new Date(Date.now() + FIFTEEN_MINUTES),
    refreshTokenValidUntil: new Date(Date.now() + ONE_DAY),
  });
};
```

Bu **`loginUser`** fonksiyonu, kullanıcının kimlik doğrulama sürecini gerçekleştirir. Kullanıcının giriş için gerekli verileri (e-posta ve şifre gibi) içeren bir **`payload`**nesnesini alır.

1. İlk olarak, fonksiyon sağlanan e-posta ile veritabanında kullanıcıyı arar. Eğer böyle bir e-posta ile kullanıcı bulunamazsa, fonksiyon 404 hatası ile kullanıcı bulunamadığını belirtir.
2. Kullanıcı bulunduğunda, fonksiyon kullanıcının girdiği şifreyi veritabanında saklanan şifre ile karşılaştırır. Bu işlem **`bcrypt`** kütüphanesi kullanılarak yapılır. Eğer şifreler eşleşmezse, 401 hatası ile kullanıcı yetkisiz olduğu bildirilir.
3. Daha sonra, fonksiyon kullanıcının önceki oturumunu, eğer varsa, oturum koleksiyonundan siler. Bu, yeni oturumla çakışmaları önlemek içindir.
4. Ardından, yeni erişim ve yenileme tokenleri oluşturulur. Kullanılan rastgele baytlar base64 formatında bir dizeye dönüştürülür.
5. Son olarak, fonksiyon veritabanında yeni bir oturum oluşturur. Yeni oturum, kullanıcı kimliğini, oluşturulan erişim ve yenileme tokenlerini ve bunların geçerlilik sürelerini içerir. Erişim tokeni sınırlı bir geçerlilik süresine (örneğin, 15 dakika) sahipken, yenileme tokeni daha uzun süre geçerlidir (örneğin, bir gün).

Bu şekilde, fonksiyon kullanıcının kimlik doğrulamasını sağlar, giriş verilerini kontrol eder, önceki oturumu siler, yeni tokenler oluşturur ve veritabanında yeni bir oturum oluşturur.
