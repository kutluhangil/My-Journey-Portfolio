# 📘 NODE.JS MODÜL SONU ÖZETİ

**1️⃣ Middleware (Ara Katmanlar)**

**Tanım:**

Middleware, Express.js içinde istek (request) ve yanıt (response) arasındaki işlemleri yöneten fonksiyonlardır.

Her istekte sıralı olarak çalışır; loglama, kimlik doğrulama, hata yönetimi gibi görevleri üstlenir.

**Örnek:**

`app.use(express.json());
app.use(logger);
app.use(authMiddleware);`

**En iyi uygulama:**

- Tek sorumluluk ilkesi (her middleware tek iş yapsın)
- Hata yakalamada `next(err)` kullanılmalı
- Global hata yakalama middleware’i bulunsun

**2️⃣ Validation (Doğrulama)**

**Amaç:**

Kullanıcılardan gelen verilerin doğru tipte ve eksiksiz olmasını sağlar.

`Joi` veya `express-validator` sıkça kullanılır.

**Örnek:**

`const loginSchema = Joi.object({
  email: Joi.string().email().required(),
  password: Joi.string().min(6).required(),
});`

**Not:**

Validation işlemini controller katmanından önce `validateBody()` middleware’iyle yapmak en güvenli yöntemdir.

**3️⃣ Authentication & Authorization (Kimlik Doğrulama ve Yetkilendirme)**

**Authentication:**

Kullanıcının kim olduğunu doğrular. (JWT, session, cookie)

**Authorization:**

Doğrulanmış kullanıcının hangi işlemleri yapmaya yetkili olduğunu belirler.

**JWT Örneği:**

`const token = jwt.sign({ id: user._id, role: user.role }, SECRET_KEY, { expiresIn: '1h' });`

**Session/Cookie Yapısı:**

- `express-session` veya `cookie-parser` ile oturum yönetimi yapılabilir.
- Refresh token ile uzun süreli oturumlar sağlanır.

**Roller:**

`admin`, `teacher`, `parent` gibi rollerle erişim kontrolü yapılabilir.

`if (req.user.role !== 'admin') throw createHttpError(403, 'Forbidden');`

**4️⃣ Google OAuth2 ile Sosyal Giriş**

**Amaç:**

Kullanıcının Google hesabı ile kimlik doğrulaması yapması.

**Akış:**

1. Google Cloud Console’da proje oluştur.
2. `google-auth-library` kur.
3. `OAuth2Client` yapılandır.
4. Auth URL üret → `generateAuthUrl()`
5. Kullanıcı Google’da giriş yapar → `validateCode()` token’ı doğrular.
6. Kullanıcı yoksa kayıt edilir, varsa giriş yapılır.

**Kod Örneği:**

`const googleOAuthClient = new OAuth2Client({
  clientId: env('GOOGLE_AUTH_CLIENT_ID'),
  clientSecret: env('GOOGLE_AUTH_CLIENT_SECRET'),
  redirectUri: '<http://localhost:3000/confirm-google-auth>',
});`

**Güvenlik:**

- `google-oauth.json` yerine çevresel değişken (.env) kullan.
- `id_token` doğrulaması `verifyIdToken()` ile yapılmalı.

**5️⃣ Swagger (API Dokümantasyonu)**

**Amaç:**

API uç noktalarının otomatik ve görsel olarak belgelenmesini sağlar.

Redocly + Swagger UI kombinasyonu ile etkileşimli API dokümanları oluşturulur.

**Yapı:**

`docs/
├── openapi.yaml
└── swagger/
    ├── paths/
    └── components/`

**Örnek Route Belgesi:**

`paths:
  /students/{id}:
    get:
      summary: Get student by id
      responses:
        '200':
          $ref: ../components/responses/200.yaml`

**Kullanım:**

- `@redocly/cli` ile `swagger.json` oluştur
- `swagger-ui-express` ile `/api-docs` rotasında yayınla

**Komutlar:**

`"build-docs": "redocly bundle --ext json -o docs/swagger.json",
"preview-docs": "redocly preview-docs"`

**6️⃣ Deploy (Dağıtım)**

**Tanım:**

Uygulamanın geliştirici ortamından üretim ortamına aktarılması süreci.

[Render.com](http://render.com/) gibi PaaS servisleri bu işlemi otomatikleştirir.

**Adımlar:**

1. Render hesabı oluştur.
2. GitHub deposunu bağla.
3. Build ve Start komutlarını belirt:

`"build": "tsc && npm run build-docs",
"start": "node dist/index.js"`

1. Çevresel değişkenleri Render panelinden tanımla.
2. Deploy et ve test et.

**En iyi uygulama:**

- `.env` dosyasını `.gitignore`’a ekle
- Log’ları Pino veya Winston ile yönet
- Swagger ve Upload dizinlerini statik olarak sun
