# Vs Code Swagger

Swagger belgelerinizi daha düzenli ve erişilebilir bir şekilde saklamak için tüm dosyaları `swagger` adında bir klasörde tutacağız. Bu klasör içerisinde iki alt klasör oluşturacağız: **`components`** ve **`paths`**.

- **`components` Klasörü**: Bu klasörde, yanıtlar veya modeller (örneğin, bir öğrenci modeli) gibi çeşitli varlıkların tanımları bulunacaktır. Bu tanımlar `schemas` alt klasöründe yer alacaktır. Gerekirse, tekrar eden kod parçalarını saklamak için ek alt klasörler oluşturulabilir.
- **`paths` Klasörü**: Bu klasörde, hangi işlemin hangi yola ve hangi HTTP metoduna karşılık geldiğini belirteceğimiz rota tanımları yer alacaktır. OpenAPI'de her bir işlemin tek bir dosyada yazılması doğru kabul edildiğinden, bu mantığa uymaya çalışacağız.

Böylece, Swagger belgelerinizin klasör yapısı aşağıdaki gibi görünebilir:

![](https://s3.eu-north-1.amazonaws.com/lms.goit.files/d6a90c4b-4a40-45ef-adcf-67da398fa599Untitled%20-%202025-01-03T214924.054.png)

- **`components/responses`**: API'nin standart yanıtları bu klasörde saklanır.
- **`components/schemas`**: API'nin veri modelleri bu klasörde bulunur.
- **`paths/students`**: Bu klasörde öğrenci kaynaklarıyla ilgili rotaların tanımları yer alacaktır. Her dosya ayrı bir işlemden sorumludur (örneğin, tüm öğrencilerin bilgilerini almak için `get.yaml`, yeni bir öğrenci kaydı oluşturmak için `post.yaml`).
- **`paths/students/{id}`**: Bu klasörde belirli bir öğrencinin ID'sine göre rotaların tanımları yer alacaktır. Her dosya ayrı bir işlemden sorumludur (örneğin, bir öğrencinin bilgilerini almak için `get.yaml` vb.).

Bu, belgelerinizin gerekli kısımlarını kolayca bulup düzenlemenize ve güncel tutmanıza yardımcı olacaktır.

Şimdi `docs/openapi.yaml` dosyasındaki `paths` alanına GET `/students/:id` tanımını yapacağımız dosyanın bağlantısını yazalım:

```
# docs/openapi.yaml

openapi: 3.1.0
info:
  version: 1.0.0
  title: Students app
  license:
    name: Apache 2.0
    url: <http://www.apache.org/licenses/LICENSE-2.0.html>
  description: >
    This is a documentation of students app
tags:
  - name: Students
    description: Operations about users.
  - name: Auth
    description: Auth operations.
servers:
  - url: <http://localhost:3000>
  - url: <https://example.com/api/v1>
paths:
  /students/{id}:
    get:
      $ref: ../swagger/paths/students/{id}/get.yaml
components:
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
```

Gördüğünüz gibi, **`$ref`** olarak belirttiğimiz yol, yukarıda incelediğimiz şemaya karşılık geliyor. Peki, **`$ref`** YAML dosyalarında ne anlama geliyor?

**`$ref`**, YAML dosyalarında, başka YAML dosyası parçalarına veya farklı dosyalara referans vermek için kullanılan özel bir anahtardır. Bu anahtar, mevcut nesnelere veya veri yapılarına atıfta bulunarak bilgi tekrarını önlemeye yardımcı olur.

Örneğin, ortak özelliklere sahip birden fazla nesneniz olduğunu düşünelim. Bu özellikleri yalnızca bir kez tanımlayarak, diğer nesnelerde onlara **`$ref`** ile referans verebilirsiniz. Bu yaklaşım, hem kod tekrarını azaltır hem de bakım sürecini kolaylaştırır. **`$ref`** kullanmanın avantajlarını ilerleyen bölümlerde daha ayrıntılı şekilde ele alacağız.
**`Not:** Şu an **$ref** alanında belirttiğimiz get.yaml dosyası boş olduğu için VSCode üzerinde bir hata mesajı görebilirsiniz. Ancak, dosyanın içeriği doldurulduğunda bu hata otomatik olarak ortadan kalkacaktır.`

Şimdi, bir öğrencinin kimlik numarasına göre bilgi alma işlemini tanımlayalım. Bunun yapısını ve içeriğini `swagger/paths/students/{id}/get.yaml` dosyasında inceleyelim.

```
# swagger/paths/studens/{id}/get.yaml
tags:
  - Students
summary: Get student by id
operationId: getStudent
description: 'Get student by id'
security:
  - bearerAuth: []
parameters:
  - in: path
    name: id
    required: true
    schema:
      type: string
      example: '65ca67e7ae7f10c88b598384'
responses:
  '200':
    description: 'Get student by id'
    content:
      application/json:
        schema:
          type: object
          required:
            - status
            - message
            - data
          properties:
            status:
              type: integer
              example: 200
            message:
              type: string
              example: Successfully found student with id 65ca67e7ae7f10c88b598384!
            data:
              type: object
              $ref: '../../../components/schemas/student.yaml'
  '401':
    $ref: '../../../components/responses/401.yaml'
```

Operasyonun tanımı şunlardan oluşur:

**1. Etiketler (tags):**

`tags:
  - Students`

Bu blok, işlemin `Students` etiketiyle gruplandırıldığını belirtir. Bu, belgelerde işlemlerin kategorize edilmesine yardımcı olur.

**2. Operasyon Tanımı (summary ve description):**

`summary: Get student by id
description: 'Get student by id'`

- `summary`: İşlemin kısa tanımı.
- `description`: İşlemin daha ayrıntılı tanımı.

**3. Benzersiz Operasyon Kimliği (operationId):**

`operationId: getStudent`

Bu, bu işlemi kodda veya belgelerde referans almak için kullanılan benzersiz bir kimliktir.

**4. Güvenlik (security):**

`security:
  - bearerAuth: []`

Bu blok, işlemi erişmek için Bearer Token (`bearerAuth`) ile kimlik doğrulamanın gerekli olduğunu belirtir; bu, `/docs/openapi.yaml` dosyasında tanımlanmıştır.

**5. Parametreler (parameters):**

```
parameters:
  - in: path
    name: id
    required: true
    schema:
      type: string
      example: '65ca67e7ae7f10c88b598384'
```

- `in: path`: Parametre yol (URL) içindedir.
- `name: id`: Parametre adı - `id`.
- `required: true`: Parametre zorunludur.
- `schema`: Parametre şeması. Veri tipinin `string` olduğunu belirtir.
- `example`: Parametre değerinin örneği.

**6. Yanıtlar (responses):**

```
responses:
  '200':
    description: 'Get student by id'
    content:
      application/json:
        schema:
          type: object
          required:
            - status
            - message
            - data
          properties:
            status:
              type: integer
              example: 200
            message:
              type: string
              example: Successfully found student with id 65ca67e7ae7f10c88b598384!
            data:
              type: object
              $ref: '../../../components/schemas/student.yaml'
  '401':
    $ref: '../../../components/responses/401.yaml'
```

- **Yanıt Kodu `200`:**`description`: Yanıtın tanımı — `Öğrenci kimliği ile al`.
- `content`: Yanıtın içeriği. Yanıtın `application/json` formatında olacağını belirtir.
- `schema`: Yanıtın şeması. Yanıt nesnesinin yapısını belirtir:
- `type: object`: Yanıt bir nesnedir.
- `required`: Zorunlu alanların listesi (`status`, `message`, `data`).
- `properties`: Yanıt nesnesinin özelliklerinin tanımı:
- `status`: Tip — `integer`, örnek — `200`.
- `message`: Tip — `string`, örnek — `Successfully found student with id 65ca67e7ae7f10c88b598384!`.
- `data`: Tip — `object`, öğrenci şemasına referans (`$ref: '../../../components/schemas/student.yaml'`).
- **Yanıt Kodu `401`:**`$ref`: `../../../components/responses/401.yaml` dosyasında `401` kodlu genel yanıt için referans.

Bu rota tanımında ayrıca öğrenci şemasına ve `401` durum koduna sahip yanıt için iki referans görüyoruz. Bunları tanımlayıp inceleyelim:

```
# swagger/components/schemas/student.yaml

type: object
required:
  - _id
  - name
  - age
  - gender
  - avgMark
  - onDuty
properties:
  _id:
    description: "Student's id"
    type: string
    example: 65e4decdd286b30065d54af9
  name:
    description: "Student's name"
    type: string
    example: 'John Doe'
  age:
    description: "Student's age"
    type: number
    example: 12
  gender:
    description: "Student's age"
    type: string
    enum: ['male', 'female', 'other']
  avgMark:
    description: "Student's average mark. Should be between 1 and 12"
    type: number
    example: 9.7
  onDuty:
    description: 'Whether is student on duty'
    type: boolean
    example: false
  parentId:
    description: "Student's parent id"
    type: string
    example: 65e4decdd286b30065d54af9
  photo:
    description: "Link to student's photo"
    type: string
    example: <https://res.cloudinary.com/uqwgdu/image/upload/image.png>
```

Bu şemada aşağıdaki unsurları görüyoruz:

**7. Nesne tipi (type):**

`type: object`

Şemanın bir nesneyi tanımladığını belirtir.

**8. Zorunlu alanlar (required):**

```
required:
  - _id
  - name
  - age
  - gender
  - avgMark
  - onDuty
```

Nesnede zorunlu olan alanların listesi.

**9. Nesne özellikleri (properties):** Özellikler, nesnenin her bir alanını tanımlar. Her bir özellik aşağıdaki niteliklere sahiptir:

- **description**: Alanın neyi temsil ettiğini açıklar.
- **type**: Alanın veri tipini belirtir (örneğin: `string`, `number`, `boolean`, vb.).
- **example**: Alan için bir örnek değer sağlar.
- **enum** (isteğe bağlı): Alanın alabileceği olası değerlerin listesini belirtir.

Aynı şeyi 401 yanıtı örneğinde de görebiliriz:

```
# swagger/components/responses/401.yaml

description: Unauthorized error
content:
  application/json:
    schema:
      type: object
      required:
        - status
        - message
        - data
      properties:
        status:
          type: integer
          example: 401
        message:
          type: string
          example: UnauthorizedError
        data:
          type: object
          required:
            - message
          properties:
            message:
              type: string
              example: 'Access token expired'
```

Ve bunu `swagger/paths/students/get.yaml` dosyasında tanımlayalım:

```
#/swagger/paths/students/get.yaml

tags:
  - Students
summary: Get list of students
operationId: getStudents
description: 'Get list of users with this endpoint'
security:
  - bearerAuth: []
parameters:
  - in: query
    name: page
    schema:
      type: integer
    example: 1
  - in: query
    name: perPage
    schema:
      type: integer
      example: 10
  - in: query
    name: sortBy
    schema:
      type: string
      example: 'age'
    description: "All student's fields can be mentioned. Default value - _id"
  - in: query
    name: sortOrder
    schema:
      type: string
      enum: ['asc', 'desc']
      example: 'asc'
  - in: query
    name: minAvgMark
    schema:
      type: number
      example: 4
  - in: query
    name: maxAvgMark
    schema:
      type: number
      example: 10
  - in: query
    name: minAge
    schema:
      type: number
      example: 10
  - in: query
    name: maxAge
    schema:
      type: number
      example: 16
  - in: query
    name: gender
    schema:
      type: string
      enum: ['male', 'female', 'other']
      example: male
responses:
  '200':
    description: Successfully found students!
    content:
      application/json:
        schema:
          type: object
          required:
            - status
            - message
            - data
          properties:
            status:
              type: integer
              example: 200
            message:
              type: string
              example: Successfully found students!
            data:
              type: object
              required:
                - data
                - page
                - perPage
                - totalItems
                - totalPages
                - hasNextPage
                - hasPreviousPage
              properties:
                data:
                  type: array
                  items:
                    $ref: '../../components/schemas/student.yaml'
                page:
                  type: number
                  example: 2
                perPage:
                  type: number
                  example: 4
                totalItems:
                  type: number
                  example: 4
                totalPages:
                  type: number
                  example: 4
                hasNextPage:
                  type: boolean
                  example: false
                hasPreviousPage:
                  type: boolean
                  example: true
  '401':
    $ref: '../../components/responses/401.yaml'
```

Bu adımda dikkatimizi çeken iki önemli nokta var:

**1. Parameters alanındaki değişiklik:**

- **`in: query`** yerine **`in: path`** kullanılmış.
- Bu, ilgili parametrenin bir sorgu parametresi olduğunu, yani `?` sembolünden sonra gelen değerleri belirttiğimizi ifade eder.

**2. 200 yanıtındaki değişiklik:**

- **`data`** alanında, aynı isimde bir alt alan daha belirmiş ve bu alan **`array`** tipiyle tanımlanmış.
- Bu tür bir şemada, dizinin elemanlarının yapısını tanımlamak için **`items`**alanını kullanabiliriz.
